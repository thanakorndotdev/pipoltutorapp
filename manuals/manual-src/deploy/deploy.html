บทที่ 1

ภาพรวม: ระบบประกอบด้วยอะไร

ทั้งระบบรันด้วย Docker Compose บนเซิร์ฟเวอร์เครื่องเดียว คำสั่งเดียวเปิดได้ทั้งหมด

บริการหน้าที่
caddyประตูหน้าบ้าน รับทุก request ที่พอร์ต 80/443 ออกใบรับรอง HTTPS ให้อัตโนมัติ (Let's Encrypt) และเสิร์ฟแผงผู้ดูแลที่ /admin/ (แผงผู้ดูแลถูก build ฝังอยู่ใน image ของ caddy)
frontendหน้าเว็บนักเรียน (Next.js)
backendAPI ที่ /api/* (Bun + Elysia) ตรวจข้อสอบ จับเวลา รับชำระเงิน สร้างและลงนามเกียรติบัตร เผยแพร่บทความตามเวลา ปิดรับโจทย์ประจำวัน ทุกครั้งที่เปิดจะอัปเดตโครงสร้างฐานข้อมูลให้เอง
postgresฐานข้อมูล PostgreSQL 16 เปิดเฉพาะ 127.0.0.1 ไม่เปิดออกอินเทอร์เน็ต
ผู้ใช้ ──https──▶ caddy ─┬─ /api/*   ──▶ backend ──▶ postgres
                         ├─ /admin/* ──▶ (ไฟล์แผงผู้ดูแลใน caddy)
                         └─ อื่น ๆ    ──▶ frontend

ข้อมูลเก็บที่ไหน

ข้อมูลทั้งหมดอยู่ใน Docker volume ไม่ได้อยู่ในโค้ด การอัปเดตหรือรีสตาร์ตไม่ทำให้หาย ชื่อจริงบนเครื่องจะขึ้นต้นด้วย docker_ เช่น docker_postgres_data

Volumeเก็บอะไรถ้าหาย
postgres_dataฐานข้อมูลทั้งหมด: ผู้ใช้ คะแนน ข้อสอบ คำสั่งซื้อ บทความ ไฟข้อมูลหายทั้งระบบ
uploads_dataรูปที่อัปโหลด (รูปโจทย์ รูปโปรไฟล์ รูปบทความ เอกสารแนบ)รูปในเว็บเสีย
certificates_dataไฟล์ PNG/PDF ของเกียรติบัตรที่ออกแล้วสร้างใหม่ได้จากหน้าแอดมิน แต่ใช้เวลา
cert_keys_dataกุญแจส่วนตัวที่ใช้ลงนามเกียรติบัตร (สร้างตอนออกใบแรก)ออกใบใหม่ด้วยกุญแจเดิมไม่ได้ ต้องสร้างกุญแจใหม่ ใบเดิมยังตรวจได้เพราะ public key อยู่ในฐานข้อมูล
caddy_dataใบรับรอง HTTPSCaddy ขอใหม่เอง

ห้ามใช้ docker compose down -v

ตัว -v ลบ volume ทั้งหมดข้างบน ถ้าต้องการหยุดระบบให้ใช้ down เฉย ๆ

บทที่ 3

เตรียมเซิร์ฟเวอร์ และติดตั้ง Docker

อย่าปิดตัวเองออกจากเครื่อง

ต้องมีบรรทัด ufw allow OpenSSH ก่อน ufw enable เสมอ ไม่อย่างนั้น SSH จะเข้าไม่ได้อีก

  1. สร้าง VPS แบบ Ubuntu 24.04 แล้วจด IP ไว้ (เช่น 203.0.113.10)
  2. เข้าเครื่องจากคอมของเรา: 
    ssh root@203.0.113.10
  3. อัปเดตเครื่อง ตั้งเวลาไทย และติดตั้ง Docker (สคริปต์ทางการของ Docker): 
    apt update && apt upgrade -y
timedatectl set-timezone Asia/Bangkok
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version   # ต้องเห็นเลขเวอร์ชันทั้งสองบรรทัด
    ระบบคำนวณวันของโจทย์ประจำวันเป็นเวลาไทยเองอยู่แล้ว การตั้งเวลาเครื่องเป็นเวลาไทยทำให้อ่าน log และตั้ง cron ง่ายขึ้น
  4. เปิดไฟร์วอลล์ให้เข้าได้เฉพาะ SSH และเว็บ: 
    ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw enable
  5. ถ้า VPS มีแรม 4 GB หรือน้อยกว่า เพิ่ม swap 2 GB กัน build ค้าง: 
    fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
บทที่ 4

ชี้โดเมนมาที่เซิร์ฟเวอร์

เข้าเว็บที่ซื้อโดเมน (หรือ Cloudflare ถ้าใช้) → จัดการ DNS → เพิ่ม record:

TypeNameValue
A@IP ของ VPS
AwwwIP ของ VPS

รอ 5 นาทีถึงไม่กี่ชั่วโมง แล้วเช็กจากคอมของเรา:

ping pipoltutor.org        # ต้องตอบกลับจาก IP ของ VPS

ถ้าใช้ Cloudflare

ช่วงแรกให้ตั้ง record เป็น DNS only (เมฆสีเทา) ก่อน เพื่อให้ Caddy ขอใบรับรอง HTTPS ได้ ใช้งานได้แล้วค่อยเปิด proxy (เมฆสีส้ม) โดยตั้ง SSL/TLS เป็น Full (strict)

บทที่ 5

ดึงโค้ด และตั้งค่า docker/.env

ไฟล์ docker/.env คือกุญแจทั้งหมดของระบบ

ห้าม commit ขึ้น GitHub (repository เป็น public) ห้ามส่งในแชต ห้ามถ่ายรูปติด เก็บสำเนาไว้ใน password manager ถ้าหายต้องสร้างรหัสใหม่ทั้งหมด

  1. ดึงโค้ดลงเครื่อง: 
    cd /opt
git clone https://github.com/thanakorndotdev/pipoltutorapp.git
cd pipoltutorapp
  2. สร้างไฟล์ตั้งค่าจากตัวอย่าง จำกัดสิทธิ์ให้ root อ่านได้คนเดียว แล้วสร้างรหัสสุ่ม: 
    cp docker/.env.example docker/.env
chmod 600 docker/.env
openssl rand -hex 24    # ใช้เป็น POSTGRES_PASSWORD
openssl rand -hex 32    # ใช้เป็น ADMIN_API_KEY
nano docker/.env
  3. แก้ค่าตามตารางหน้าถัดไป แล้วบันทึก (nano: Ctrl+O, Enter, Ctrl+X)

ตัวอย่างส่วนที่ต้องแก้

POSTGRES_PASSWORD=<รหัสสุ่ม>
ALLOW_DEV_AUTH=0
ADMIN_EMAILS=owner.a@gmail.com
OWNER_EMAILS=owner.a@gmail.com,owner.b@gmail.com
ADMIN_API_KEY=<รหัสสุ่ม>
SITE_ADDRESS="pipoltutor.org, www.pipoltutor.org"
PUBLIC_URL_DOCKER=https://pipoltutor.org
GOOGLE_CLIENT_ID=<...>.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=<...>
OMISE_PUBLIC_KEY=pkey_<...>
OMISE_SECRET_KEY=skey_<...>

บรรทัด SITE_ADDRESS และ PUBLIC_URL_DOCKER ในไฟล์ตัวอย่างขึ้นต้นด้วย # (ปิดไว้) ต้องลบ # ออกด้วย

ค่าใน docker/.env สำหรับเว็บจริง

ตัวแปรค่าที่ใส่
POSTGRES_PASSWORDรหัสสุ่มจาก openssl rand -hex 24 (ห้ามใช้ change-me) ตั้งครั้งเดียว เปลี่ยนหลังติดตั้งแล้วจะต่อฐานข้อมูลไม่ได้
POSTGRES_USER / POSTGRES_DB
POSTGRES_PORT / BACKEND_PORT		ใช้ค่าเดิมจากตัวอย่างได้ ห้ามเปลี่ยนหลังติดตั้ง
ALLOW_DEV_AUTH0 เท่านั้น ถ้าเป็น 1 ใครก็สวมรอยเป็นใครก็ได้
OWNER_EMAILSอีเมล Google ของ Owner อย่างน้อย 2 อีเมล คั่นด้วยจุลภาค ได้สิทธิ์ Owner (จัดการสิทธิ์ทีมงาน กุญแจลงนาม ระยะเก็บข้อมูล) ถ้าว่าง ไม่มีใครเปิดเมนู "ผู้ใช้และสิทธิ์" ได้
ADMIN_EMAILSอีเมลที่ได้บทบาทผู้ดูแลระบบตอนเข้าสู่ระบบครั้งแรก ใส่อีเมล Owner ก็พอ ทีมงานคนอื่นให้ Owner มอบสิทธิ์ผ่านหน้าเว็บ
ADMIN_API_KEYรหัสสุ่มจาก openssl rand -hex 32 ใช้เป็นทางเข้าฉุกเฉินของแผงผู้ดูแล (สิทธิ์เต็ม) เก็บไว้กับผู้ดูแลเซิร์ฟเวอร์เท่านั้น
SITE_ADDRESS"pipoltutor.org, www.pipoltutor.org" Caddy ขอ HTTPS ให้ทั้งสองชื่อ
PUBLIC_URL_DOCKERhttps://pipoltutor.org ใช้ทั้งลิงก์ล็อกอิน Google และลิงก์ QR บนเกียรติบัตร ต้องตั้งให้ถูกก่อนออกใบแรก
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET		จาก Google Cloud Console (บทที่ 8)
OMISE_PUBLIC_KEY
OMISE_SECRET_KEY		Live keys จาก dashboard.omise.co → Keys
CLOUDFLARE_ACCOUNT_ID
CLOUDFLARE_API_TOKEN		ไม่บังคับ (ดูดวงด้วย AI) CLOUDFLARE_AI_MODEL ใช้ค่าเดิม
BACKUP_AGE_RECIPIENT
BACKUP_INTERVAL_SECONDS		ใช้เฉพาะชุดสำรองแบบเข้ารหัส (บทที่ 12) ยังไม่ใช้เว้นว่างได้

แก้ .env แล้วต้องสั่ง up -d ใหม่

ค่าใน .env ถูกอ่านตอนสร้าง container เท่านั้น แก้แล้วรัน docker compose -f docker/docker-compose.yml up -d อีกครั้ง

บทที่ 6

เปิดระบบ และตรวจว่าใช้ได้

ตั้งชื่อย่อให้คำสั่ง

พิมพ์ครั้งเดียวต่อการเข้าเครื่อง แล้วใช้ dc ps, dc logs -f backend แทนคำสั่งยาวได้ (ใส่ไว้ใน ~/.bashrc เพื่อให้มีทุกครั้ง)

alias dc='docker compose -f /opt/pipoltutorapp/docker/docker-compose.yml'
  1. ตรวจไฟล์ตั้งค่า แล้ว build และเปิดทั้งหมด (ครั้งแรกประมาณ 5–10 นาที): 
    cd /opt/pipoltutorapp
# ไม่มีข้อความ = ถูกต้อง
docker compose -f docker/docker-compose.yml config --quiet
docker compose -f docker/docker-compose.yml up -d --build
    ถ้าขึ้น set POSTGRES_USER in docker/.env แปลว่ายังไม่ได้สร้าง docker/.env
  2. ดูสถานะ ทุกบริการต้องขึ้น Up และ postgres ขึ้น healthy: 
    dc ps
  3. เช็ก API, HTTPS และการ redirect: 
    # ต้องได้ {"status":"ok","db":"up",...}
curl https://pipoltutor.org/api/health
curl -sI http://pipoltutor.org | head -3          # ต้อง redirect ไป https
curl -sI https://pipoltutor.org | grep -i strict-transport   # ต้องมี HSTS
  4. ตรวจว่า backend ได้ค่า Owner แล้ว (ต้องเห็นอีเมลที่ใส่): 
    dc exec -T backend printenv OWNER_EMAILS
  5. เปิด https://pipoltutor.org ในเบราว์เซอร์ ต้องเห็นรูปกุญแจ (HTTPS) และหน้าแรก
  6. (ครั้งแรกเท่านั้น) ใส่ข้อมูลเริ่มต้น: สินค้าและราคา วันสอบ และชุดข้อสอบตัวอย่าง mock-100 
    dc exec backend bun run db:seed
    สคริปต์ไม่เขียนทับข้อมูลที่มีอยู่ รันซ้ำได้ ชุดตัวอย่างซ่อนหรือลบได้ในแผงผู้ดูแล
  7. เปิด https://pipoltutor.org/admin/ แล้วเข้าสู่ระบบด้วย Google ของ Owner ต้องเข้าแผงผู้ดูแลได้ จากนั้นทำบทที่ 7

backend รันงานเบื้องหลังเองทุก 30 วินาที: สร้างไฟล์เกียรติบัตรในคิว เผยแพร่บทความที่ตั้งเวลา ปิดรับโจทย์ประจำวันตอนเที่ยงคืน และลบ log ตามระยะเก็บข้อมูลที่อนุมัติ ไม่ต้องตั้ง cron เพิ่มสำหรับงานเหล่านี้

บทที่ 7

ตั้ง Owner และค่าเริ่มต้นในแผงผู้ดูแล

ทำครั้งเดียวหลังเปิดระบบครั้งแรก รายละเอียดหน้าจออยู่ในคู่มือการใช้งาน

  1. Owner A เข้า /admin/ → ผู้ใช้และสิทธิ์
  2. ให้ Owner B เข้าสู่ระบบที่หน้าเว็บหนึ่งครั้งก่อน (บัญชีจะได้ขึ้นในรายการ)
  3. กด สิทธิ์โมดูล ของ Owner A และ Owner B → เลือกแม่แบบ Owner → ใส่เหตุผล → บันทึก เมื่อบันทึกแล้ว ค่าในฐานข้อมูลจะใช้แทน OWNER_EMAILS ระบบไม่ยอมให้ถอด Owner จนเหลือ 0 คน
  4. มอบสิทธิ์ทีมงานคนอื่นตามหน้าที่ (Admin, Author, Moderator, Results Viewer)
  5. เมนู ประวัติและระยะเก็บข้อมูล → ระยะเก็บข้อมูล ทบทวนค่าที่เสนอ (log 30 วัน หมวดอื่น 365 วัน) แล้วกด อนุมัติ
  6. เมนู วันสอบ ตั้งวันสอบ จภ. และวันปิดรับสมัคร
  7. เมนู สินค้าและราคา ตรวจราคา ปิดขายสินค้าที่ไม่ใช้
  8. ออกเกียรติบัตรทดสอบหนึ่งใบด้วยบัญชีผู้ทดสอบ แล้วสแกน QR ด้วยมือถือ ต้องเปิดหน้าตรวจสอบบนโดเมนจริงและขึ้น "ใช้ได้" จากนั้นสำรองกุญแจทันที (บทที่ 10)
# หลังออกใบแรกต้องมีไฟล์ .pem สิทธิ์ -rw-------
dc exec -T backend ls -la /app/cert-keys

บทที่ 9

อัปเดตเวอร์ชันใหม่ โดยข้อมูลไม่หาย

ข้อมูลอยู่ใน Docker volume (บทที่ 1) การอัปเดตเปลี่ยนแค่โปรแกรม ข้อมูลจึงอยู่ครบ ถ้าทำตามบทนี้และไม่ใช้คำสั่งในกรอบแดงหน้าถัดไป

วิธีที่แนะนำ: ใช้สคริปต์ deploy.sh (คำสั่งเดียว)

cd /opt/pipoltutorapp
sh docker/deploy.sh

สคริปต์ทำ 6 ขั้นตามลำดับ และหยุดทันทีถ้าขั้นไหนไม่ผ่าน:

  1. เช็กว่ามีนักเรียนกำลังสอบอยู่ไหม ถ้ามี จะหยุดและบอกจำนวนคน ให้รอจนเขาส่ง
  2. สำรอง ฐานข้อมูล รูปที่อัปโหลด ไฟล์เกียรติบัตร และกุญแจลงนาม ไว้ที่ /opt/backups พร้อมจดเลขเวอร์ชันเดิม ถ้าไฟล์สำรองฐานข้อมูลว่างจะไม่อัปเดตต่อ
  3. ดึงโค้ดใหม่ จาก GitHub (git pull --ff-only ถ้าบนเซิร์ฟเวอร์มีไฟล์ที่ถูกแก้เอง จะหยุดแทนการเขียนทับ)
  4. build เวอร์ชันใหม่ ระหว่างนี้เว็บเดิมยังเปิดให้ใช้ตามปกติ
  5. สลับไปเวอร์ชันใหม่ เว็บสะดุดประมาณ 10–30 วินาที backend อัปเดตโครงสร้างฐานข้อมูลให้เอง
  6. รอจน backend ตอบว่าปกติ แล้วพิมพ์ว่าอัปเดตจากเวอร์ชันไหนไปเวอร์ชันไหน และไฟล์สำรองอยู่ที่ไหน
ตัวเลือกใช้เมื่อ
FORCE=1 sh docker/deploy.shต้องอัปเดตด่วนทั้งที่มีคนกำลังสอบ คำตอบที่เซฟแล้วไม่หาย หน้าเว็บของนักเรียนลองเซฟซ้ำให้เอง แต่เวลาสอบยังเดินต่อระหว่างที่เว็บสะดุด
BACKUP_DIR=/ที่อื่น sh docker/deploy.shอยากเก็บไฟล์สำรองไว้โฟลเดอร์อื่น

ตัวอย่างผลลัพธ์เมื่อสำเร็จ:

==> 1/6 Checking for exams in progress
students mid-exam: 0
==> 2/6 Backing up database and uploads to /opt/backups
...
Done: 0e42332 -> 6bf0f12. Backup: /opt/backups/db-20261121-030000.dump

ถ้าจะทำเองทีละคำสั่ง (ไม่ใช้สคริปต์)

cd /opt/pipoltutorapp
# 1) สำรองก่อนเสมอ (ฐานข้อมูล รูป เกียรติบัตร กุญแจ)
sh docker/nightly-backup.sh
git rev-parse --short HEAD         # จดเลขเวอร์ชันเดิมไว้
# 2) ดึงโค้ด แล้ว build ก่อนสลับ
git pull --ff-only
dc build
dc up -d
# 3) ตรวจ
curl https://pipoltutor.org/api/health

ห้ามใช้คำสั่งเหล่านี้ ข้อมูลจะหาย

  • docker compose down -v — ตัว -v ลบฐานข้อมูล รูป เกียรติบัตร และกุญแจทั้งหมด
  • docker volume rm … / docker volume prune / docker system prune --volumes
  • bun run db:push บนเซิร์ฟเวอร์จริง (โครงสร้างฐานข้อมูลอัปเดตเองตอน backend เริ่ม)
  • ลบโฟลเดอร์ /opt/pipoltutorapp แล้ว clone ใหม่โดยไม่ได้เก็บ docker/.env ไว้
  • เปลี่ยน POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB ใน .env หลังติดตั้งแล้ว
  • แก้โค้ดบนเซิร์ฟเวอร์โดยตรง (ครั้งหน้า git pull จะชนกัน) ให้แก้บนเครื่องพัฒนาแล้ว push ขึ้น GitHub

ช่วงเวลาที่ควรอัปเดต

  • ช่วงที่ไม่มีรอบสอบ เช่น ดึก หรือวันที่ไม่ได้นัดสอบ ไม่อัปเดตก่อนรอบสอบใหญ่ไม่กี่ชั่วโมง
  • หลีกเลี่ยงช่วง 23:50–00:10 ซึ่งเป็นช่วงปิดรับและเปิดโจทย์ประจำวัน
  • หลังอัปเดต ลองล็อกอิน ทำข้อสอบชุดทดสอบ ทำโจทย์ประจำวัน และเปิด /admin/ ทุกครั้ง

ถ้าเวอร์ชันใหม่มีปัญหา: ย้อนกลับ

กรณีที่ 1: โค้ดมีปัญหา แต่ข้อมูลปกติ (เจอบ่อยที่สุด) ย้อนแค่โค้ด ข้อมูลไม่เปลี่ยน การอัปเดตโครงสร้างฐานข้อมูลของระบบนี้เป็นแบบเพิ่มอย่างเดียว (ไม่ลบตารางหรือคอลัมน์) โค้ดเวอร์ชันก่อนจึงยังใช้ฐานข้อมูลใหม่ได้

cat /opt/backups/version-before-*.txt | tail -1    # เลขเวอร์ชันก่อนอัปเดต
git checkout <เลขเวอร์ชันนั้น>
dc up -d --build

แก้เสร็จแล้วกลับมาใช้เวอร์ชันล่าสุดด้วย git checkout main แล้วรัน sh docker/deploy.sh อีกครั้ง

กรณีที่ 2: ข้อมูลเสียหายจากเวอร์ชันใหม่ กู้ฐานข้อมูลจากไฟล์ที่สคริปต์สำรองไว้ก่อนอัปเดตตามบทที่ 11 แล้วค่อยย้อนโค้ดตามกรณีที่ 1 แจ้งทีมพัฒนาก่อนทุกครั้ง

บทที่ 10

สำรองข้อมูล

ต้องสำรอง 4 อย่าง: ฐานข้อมูล, รูปที่อัปโหลด, ไฟล์เกียรติบัตร และกุญแจลงนาม สคริปต์ docker/nightly-backup.sh ทำทั้งหมดในคำสั่งเดียว

10.1 สำรองด้วยมือ

cd /opt/pipoltutorapp
sh docker/nightly-backup.sh

ได้ไฟล์ใน /opt/backups (สิทธิ์ root อ่านได้คนเดียว) เช่น

db-20261121-030000.dump           # ฐานข้อมูล
uploads-20261121-030000.tgz       # รูปที่อัปโหลด
certificates-20261121-030000.tgz  # ไฟล์เกียรติบัตร PNG/PDF
cert-keys-20261121-030000.tgz     # กุญแจลงนาม (มีหลังออกใบแรก)

ตัวเลือก: BACKUP_DIR=/ที่อื่น เปลี่ยนโฟลเดอร์ และ KEEP_DAYS=30 เปลี่ยนจำนวนวันที่เก็บ (ค่าเริ่มต้น 14 วัน สคริปต์ลบเฉพาะไฟล์สำรองของตัวเองที่เก่ากว่านั้น)

10.2 สำรองอัตโนมัติทุกคืน (ตี 3)

รัน 10.1 ด้วยมือก่อนหนึ่งครั้ง (สร้างโฟลเดอร์ /opt/backups) แล้วพิมพ์ crontab -e และเพิ่มบรรทัดนี้ (บรรทัดเดียว):

0 3 * * * sh /opt/pipoltutorapp/docker/nightly-backup.sh >> /opt/backups/nightly.log 2>&1

เช็กผลวันถัดไปด้วย tail /opt/backups/nightly.log ต้องเห็นบรรทัด backup ok

10.3 เก็บไฟล์สำรองไว้นอกเซิร์ฟเวอร์

ไฟล์ใน /opt/backups อยู่บนเครื่องเดียวกับระบบ

ถ้าเครื่องเสียหรือผู้ให้บริการปิดบัญชี ไฟล์สำรองหายไปด้วย ต้องคัดลอกออกไปเก็บที่อื่นเป็นประจำ อย่างน้อยสัปดาห์ละครั้ง และทุกครั้งหลังรอบสอบใหญ่

จากคอมของ Owner (macOS/Linux):

mkdir -p ~/pipoltutor-backups
rsync -av root@203.0.113.10:/opt/backups/ ~/pipoltutor-backups/   # คัดลอกเฉพาะไฟล์ใหม่
  • ไฟล์สำรองมีข้อมูลนักเรียนและกุญแจลงนาม เก็บในที่ที่จำกัดสิทธิ์ ไม่แชร์ลิงก์สาธารณะ
  • ถ้าใช้ object storage ตั้ง sync อัตโนมัติด้วย rclone โดยใช้ credential ของ Owner
  • ไฟล์ cert-keys-*.tgz สำคัญที่สุดและเล็กมาก เก็บสำเนาไว้มากกว่าหนึ่งที่
บทที่ 11

กู้คืนข้อมูล

อ่านก่อนกู้

  • ข้อมูลที่เกิดหลังเวลาของไฟล์สำรองจะหาย (เช่น คนสมัครหรือสอบหลังเวลานั้น) แจ้งทีมพัฒนาก่อนทุกครั้ง
  • วิธีในบทนี้ไม่เขียนทับฐานข้อมูลเดิม แต่กู้ลงฐานใหม่ ตรวจ แล้วสลับชื่อ ฐานเดิมถูกเก็บไว้ในชื่อ before_restore ย้อนกลับได้
  • ทำตอนไม่มีคนสอบ เว็บจะปิดระหว่างกู้ (หลายนาทีตามขนาดข้อมูล)

11.1 กู้ฐานข้อมูล

  1. หยุดเว็บและ API (postgres ยังทำงานอยู่): 
    cd /opt/pipoltutorapp
dc stop backend frontend
  2. สร้างฐานใหม่ชื่อ restore_check แล้วกู้ไฟล์สำรองลงไป (เปลี่ยนชื่อไฟล์เป็นไฟล์ที่ต้องการ): 
    dc exec -T postgres sh -c 'createdb -U "$POSTGRES_USER" restore_check'
dc exec -T postgres sh -c \
  'pg_restore -U "$POSTGRES_USER" -d restore_check --no-owner --exit-on-error' \
  < /opt/backups/db-20261121-030000.dump
  3. ตรวจว่าข้อมูลครบ (จำนวนผู้ใช้และการสอบต้องสมเหตุสมผล): 
    dc exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d restore_check \
  -c "select count(*) from users" -c "select count(*) from attempts"'
  4. สลับชื่อ: ฐานปัจจุบันเปลี่ยนเป็น before_restore และฐานที่กู้เปลี่ยนเป็นชื่อหลัก: 
    dc exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d postgres \
  -c "ALTER DATABASE \"$POSTGRES_DB\" RENAME TO before_restore" \
  -c "ALTER DATABASE restore_check RENAME TO \"$POSTGRES_DB\""'
  5. เปิดระบบและตรวจ: 
    dc start backend frontend
curl https://pipoltutor.org/api/health
  6. ใช้งานไปสักระยะจนแน่ใจแล้ว ค่อยลบฐานเดิม (ถ้ายังมี before_restore จากครั้งก่อน ต้องลบก่อนกู้ครั้งใหม่): 
    dc exec -T postgres sh -c \
  'psql -U "$POSTGRES_USER" -d postgres -c "DROP DATABASE before_restore"'

ถ้ากู้แล้วมีปัญหา ย้อนกลับไปใช้ฐานเดิมด้วยการหยุด backend/frontend แล้วสลับชื่อกลับ (ขั้นที่ 4 กลับด้าน: ชื่อหลัก → restore_check และ before_restore → ชื่อหลัก)

11.2 กู้รูป ไฟล์เกียรติบัตร และกุญแจลงนาม

ใช้เมื่อ volume ของไฟล์หาย เช่น ย้ายเครื่องใหม่ คำสั่งแตกไฟล์สำรองกลับเข้า volume ผ่าน container backend (ต้องเปิด backend อยู่):

cd /opt/pipoltutorapp
B=/opt/backups; S=20261121-030000    # S = เวลาในชื่อไฟล์สำรองที่จะกู้
dc exec -T backend sh -c 'tar xzf - -C /app/uploads' < $B/uploads-$S.tgz
dc exec -T backend sh -c 'tar xzf - -C /app/certificates' < $B/certificates-$S.tgz
dc exec -T backend sh -c 'tar xzf - -C /app/cert-keys' < $B/cert-keys-$S.tgz
# ไฟล์ .pem ต้องเป็น -rw-------
dc exec -T backend ls -la /app/cert-keys

ตรวจผล: เปิดหน้าตรวจสอบเกียรติบัตรใบเก่าจาก QR ต้องขึ้น "ใช้ได้" และลายเซ็นถูกต้อง ดาวน์โหลด PNG/PDF ได้ และรูปโจทย์แสดงครบ

11.3 ย้ายไปเซิร์ฟเวอร์เครื่องใหม่

  1. บนเครื่องเก่า: sh docker/nightly-backup.sh แล้วคัดลอกไฟล์ชุดล่าสุดทั้ง 4 ไฟล์ และ docker/.env ออกมา
  2. บนเครื่องใหม่: ทำบทที่ 3–5 โดยใช้ docker/.env เดิม (รหัสฐานข้อมูลเดิม)
  3. dc up -d --build แล้วทำ 11.1 (กู้ฐานข้อมูล) และ 11.2 (กู้ไฟล์)
  4. ย้าย DNS มาที่ IP ใหม่ (บทที่ 4) รอ Caddy ออก HTTPS แล้วตรวจตามบทที่ 6
  5. ปิดเครื่องเก่าหลังตรวจครบ อย่าเปิดทั้งสองเครื่องรับผู้ใช้พร้อมกัน

ซ้อมกู้คืนเดือนละครั้ง

ไฟล์สำรองที่ไม่เคยลองกู้ อาจใช้ไม่ได้ตอนจำเป็น ลองกู้ตาม 11.1 ขั้นที่ 2–3 ลงฐาน restore_check (ไม่ต้องสลับ) แล้วลบทิ้งด้วย DROP DATABASE restore_check ใช้เวลาไม่กี่นาทีและไม่กระทบเว็บ

บทที่ 12

สำรองแบบเข้ารหัสและกู้ย้อนเวลา (ทางเลือกขั้นสูง)

ชุดเสริม docker/docker-compose.backup.yml สร้างไฟล์สำรองที่เข้ารหัสทุกวัน และเก็บ WAL ของฐานข้อมูลต่อเนื่อง ทำให้กู้ฐานข้อมูลย้อนไปเวลาใดก็ได้ (PITR) เหมาะเมื่อมีผู้ดูแลระบบที่คุ้นกับ PostgreSQL ถ้ายังไม่พร้อม บทที่ 10–11 เพียงพอสำหรับเริ่มต้น

เปิดใช้

  1. บนคอมของ Owner (ไม่ใช่เซิร์ฟเวอร์) ติดตั้ง age แล้วสร้างคู่กุญแจ: 
    # เก็บไฟล์นี้ไว้กับ Owner เท่านั้น ใช้ถอดรหัสตอนกู้
age-keygen -o pipol-backup.key
    คัดลอกเฉพาะบรรทัด public key: age1…
  2. ใส่ใน docker/.env บนเซิร์ฟเวอร์: 
    BACKUP_AGE_RECIPIENT=age1...
BACKUP_INTERVAL_SECONDS=86400
  3. ตอนไม่มีคนสอบ (ฐานข้อมูลจะรีสตาร์ตไม่กี่วินาที) เปิดระบบพร้อมชุดเสริม: 
    cd /opt/pipoltutorapp
alias dcb='docker compose -f docker/docker-compose.yml -f docker/docker-compose.backup.yml'
dcb config --quiet
dcb up -d --build
  4. เช็กว่าสำรองสำเร็จ: dcb logs backups ต้องเห็น Encrypted DB/base/WAL/assets backup completed

เมื่อเปิดชุดเสริมแล้ว

  • ทุกคำสั่ง up หลังจากนี้ต้องใช้ dcb (ใส่ -f ทั้งสองไฟล์) ไม่อย่างนั้นการเก็บ WAL จะถูกปิด
  • ไฟล์ .tar.gz.age อยู่ใน volume backups_data และ WAL ใน wal_archive ระบบยังไม่ลบไฟล์เก่าเอง ต้องเฝ้าพื้นที่ดิสก์ (df -h) และคัดลอกออกนอกเครื่องเป็นประจำ
  • ถ้าทำกุญแจ pipol-backup.key หาย ไฟล์สำรองชุดนี้ถอดรหัสไม่ได้อีกเลย

ขั้นตอนกู้ย้อนเวลา (ถอดรหัส, วาง base backup, ตั้ง recovery_target_time) อยู่ใน manuals/operations-guide.md หัวข้อ "กู้คืนจริง" ให้ทีมพัฒนาหรือผู้ดูแล PostgreSQL ทำ และกู้ลงเครื่องหรือฐานใหม่เสมอ ห้ามทับของจริง

บทที่ 13

งานดูแลประจำ และกรณีฉุกเฉิน

ตรวจประจำ

ความถี่ตรวจอะไร
ทุกวัน (สัปดาห์แรก)tail /opt/backups/nightly.log มี backup ok · dc ps ทุกบริการ Up · หน้าภาพรวมในแผงผู้ดูแล: คิวเกียรติบัตร ข้อผิดพลาดใหม่ · โจทย์ประจำวันพรุ่งนี้พร้อม
ทุกสัปดาห์คัดลอกไฟล์สำรองออกนอกเครื่อง · df -h พื้นที่ดิสก์เหลือมากกว่า 20% · dc logs --tail 200 backend ไม่มี error ซ้ำ ๆ
ทุกเดือนซ้อมกู้คืน (11.3) · อัปเดตระบบปฏิบัติการ apt update && apt upgrade -y แล้ว reboot ตอนไม่มีคนสอบ · ทบทวนรายชื่อทีมงานในผู้ใช้และสิทธิ์

ดิสก์ใกล้เต็มจาก image เก่า: docker image prune -f (ไม่ลบ volume ข้อมูล)

Owner ทุกคนเข้าระบบไม่ได้

  1. ผู้ดูแลเซิร์ฟเวอร์ที่ Owner แต่งตั้ง เปิด /admin/ แล้ววาง ADMIN_API_KEY ในช่อง API key
  2. ไปที่ ผู้ใช้และสิทธิ์ คืนสิทธิ์ Owner ให้บัญชี Google ที่ตรวจสอบตัวตนแล้ว
  3. ทบทวนเมนู ประวัติและระยะเก็บข้อมูล ว่ามีการเปลี่ยนแปลงที่ผิดปกติไหม

สงสัยว่ารหัสรั่ว

  • ADMIN_API_KEY: สร้างใหม่ด้วย openssl rand -hex 32 ใส่ใน .env แล้ว dc up -d backend
  • GOOGLE_CLIENT_SECRET / OMISE_SECRET_KEY: สร้างใหม่ในหน้า Google Cloud / Omise แล้วใส่ใน .env และ dc up -d backend
  • กุญแจลงนามเกียรติบัตร: Owner กด "เปลี่ยนกุญแจ (Key rotation)" ในเมนูเกียรติบัตร ใบเดิมยังตรวจได้ แล้วสำรองกุญแจใหม่ทันที
  • POSTGRES_PASSWORD: ฐานข้อมูลไม่เปิดออกอินเทอร์เน็ต ถ้าต้องเปลี่ยนจริง ให้ทีมพัฒนาทำ เพราะต้องเปลี่ยนในฐานข้อมูลก่อนแก้ .env
บทที่ 14

แก้ปัญหาที่พบบ่อย

อาการสาเหตุและวิธีแก้
เปิดเว็บไม่ขึ้น / ไม่มี HTTPSDNS ยังไม่ชี้มา หรือไฟร์วอลล์ปิดพอร์ต 80/443 ดู dc logs caddy หาคำว่า certificate
/api/... ขึ้น 502backend ล่มหรือยังเปิดไม่เสร็จ ดู dc logs backend ถ้ารีสตาร์ตวนซ้ำ มักเป็นปัญหาตอนอัปเดตฐานข้อมูล ข้อความ NOTICE "already exists, skipping" เป็นเรื่องปกติ
/api/health ขึ้น "db":"down"postgres ไม่ทำงาน หรือรหัสใน .env ไม่ตรงกับตอนสร้างฐานข้อมูลครั้งแรก
ล็อกอิน Google ไม่ได้ดูบทที่ 8 ตรวจ redirect URI และ consent screen ต้องเป็น In production
Owner เข้าเมนูผู้ใช้และสิทธิ์ไม่ได้ (403)OWNER_EMAILS ว่างหรือสะกดผิด ตรวจด้วย dc exec -T backend printenv OWNER_EMAILS แก้ .env แล้ว dc up -d backend
เข้า /admin/ แล้วขึ้น "บัญชี … ยังไม่มีสิทธิ์"บัญชีนั้นยังไม่ได้รับสิทธิ์ทีมงาน ให้ Owner มอบสิทธิ์
จ่ายเงินแล้วสิทธิ์ไม่เปิดตรวจ webhook ใน Omise ว่าส่งถึง /api/webhooks/omise และใช้คีย์ Live ทั้งสองตัว
QR บนเกียรติบัตรพาไป localhostออกใบก่อนตั้ง PUBLIC_URL_DOCKER แก้ .env → dc up -d backend แล้วในเมนูเกียรติบัตรกด "ออกใบใหม่ตามเทมเพลต" ของชุดที่กระทบ
เกียรติบัตรค้าง "รอสร้างไฟล์" หรือ "สร้างไม่สำเร็จ"ดู dc logs backend และพื้นที่ดิสก์ แก้แล้วกด "สร้างไฟล์ใหม่" ในเมนูเกียรติบัตร
แก้ .env แล้วไม่มีผลต้องสั่ง dc up -d ใหม่ทุกครั้งหลังแก้
build ค้างหรือ "Killed"แรมไม่พอ เพิ่ม swap (บทที่ 3) หรืออัปเกรด VPS
ดิสก์เต็มdocker image prune -f ลบ image เก่า ลด KEEP_DAYS ของไฟล์สำรอง หรือย้ายไฟล์สำรองเก่าออก

คำสั่งดู log:

dc logs -f backend          # ดูต่อเนื่อง กด Ctrl+C เพื่อออก
dc logs --tail 200 caddy
