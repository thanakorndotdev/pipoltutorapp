# Frontend conventions

App lives in `frontend/pipoltutor-app`. Stack: Next.js 16.3.4, React 19.2.8, Tailwind CSS v4, TypeScript strict, Bun 1.2.23 as package manager and runtime.

## Read the local Next docs first

`AGENTS.md` in the app root carries a warning written by `next dev` itself: **this Next version has breaking changes against training data.** Before writing routing, caching, params, or config code, read the relevant guide under `frontend/pipoltutor-app/node_modules/next/dist/docs/` (`01-app/` for App Router, `03-architecture/`). Do not write App Router code from memory and do not assume Next 14/15 behaviour.

The `<!-- BEGIN:nextjs-agent-rules -->` block in `AGENTS.md` is regenerated by `next dev`. Deleting it from a diff only recreates it; commit it with the work instead.

## Commands

```bash
cd frontend/pipoltutor-app
bun run dev      # next dev on :3000
bun run build    # next build — also what the Docker image runs
bun run lint     # eslint (flat config, eslint-config-next core-web-vitals + typescript)
```

Use `bun`, never `npm`/`yarn`/`pnpm` — `bun.lock` is the lockfile and the Dockerfile installs with `--frozen-lockfile`. Adding a dependency means running `bun add` so the lockfile updates, otherwise the image build fails.

`sharp` and `unrs-resolver` are in `ignoreScripts` and `trustedDependencies`; leave both lists alone unless a native build actually breaks.

## Layout

```
app/
  layout.tsx     root layout
  page.tsx       landing
  globals.css    Tailwind v4 entry + design tokens
  favicon.ico
```

- App Router only. Route folders under `app/`, colocated `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`.
- Import alias is `@/*` → app root (`tsconfig.json` paths). Use `@/...`, not long relative chains.
- Server Components are the default. Add `"use client"` only for a component that needs state, effects, or event handlers, and push it as far down the tree as possible — the exam question card is interactive, the page shell around it is not.
- TypeScript is `strict`. No `any` on data crossing a boundary; type API responses.

## Talking to the backend

In production everything is same-origin behind Caddy: `/api/*` reaches the Elysia backend, everything else is the Next app. So client-side calls are relative — `fetch("/api/health")` — with no host and no CORS.

In the host dev loop (`bun run dev` on 3000, backend on 3001) Caddy is not in the path. Route through the dev proxy or an env-driven base URL rather than hardcoding `http://localhost:3001` in a component; the same literal will break inside Docker, where the backend is reachable as `backend:3001` and only from server-side code.

Server Components can call the backend directly; the browser cannot reach `backend:3001`. Anything a client component fetches must go through `/api/*`.

## What must never reach the browser

The exam engine's whole value is that the answer key is not in the client bundle or any client payload (`PRODUCT.md`, and the `exam-engine-rules` skill). Concretely, in this app:

- Never pass `correctChoice` or an unsubmitted attempt's `explanation` into a Client Component's props — props are serialized into the HTML payload and are readable in View Source.
- Never fetch a raw questions row into client code. Ask the backend for a client-safe shape.
- Never put grading, scoring, or timer authority in the browser. The countdown is decoration; `attempts.expiresAt` on the server decides.
- Secrets belong in server-only code. A `NEXT_PUBLIC_` variable is public — treat the prefix as "printed on the page".

## Styling

Tailwind v4 via `@tailwindcss/postcss`, configured in CSS. `globals.css` starts with `@import "tailwindcss";` and declares tokens in `:root` + `@theme inline` — there is no `tailwind.config.js`, so new design tokens go in `@theme inline`, not a JS config.

All colour, type, spacing, and Thai line-height rules live in the `thai-ui` and `design-system` skills. Load one of those before styling anything user-facing rather than picking values here.

## Known scaffold debt

`app/layout.tsx` and `globals.css` are still create-next-app defaults: `lang="en"`, Geist/Geist_Mono fonts, `font-family: Arial, Helvetica, sans-serif` on `body`, and the "Create Next App" metadata. The product is Thai. Any real page work should replace these with `lang="th"`, the Mitr/Anuphan pairing, and the product palette — see `thai-ui`.
